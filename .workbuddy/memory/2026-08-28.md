## DifyRealDialog 接入真实会话列表接口
- 真实接口：`http://10.89.34.77:8080/session/list`，返回 `{ code, msg, data: [{ cache, content, id, sessionId, state }] }`。
- `vite.config.ts`：新增 dev 代理 `/dify-session` → 目标 `env.VITE_APP_DIFY_SESSION_HOST || 'http://10.89.34.77:8080'`（rewrite 去掉前缀），规避浏览器跨域。**需重启 vite 生效**。
- `DifyRealDialog.vue`：
  - 引入 `@/utils/request`；`fetchConversationList()` 改为 `request.get('/dify-session/session/list', { baseURL: '' })`（baseURL:'' 走同源代理）。
  - 字段映射：id=String(id)、title=cache、preview=content、sessionId/state 透传；接口无时间字段，`updateTime` 暂空。
  - `ConversationItem` 接口扩展 `sessionId?/state?/preview?`；列表项副标题改为 `conv.preview || conv.updateTime`。
- 假设：标题取 `cache`、副标题取 `content`；若后端语义不同（如用 content 作标题）可一处调整。消息详情接口（selectConversation 拉历史消息）尚未提供，仍占位。
- 微调：用户要求列表项**只显示 content**。改动：`fetchConversationList` 映射 `title = item.content`、删除 `preview` 行；模板移除 `.conversation-item-time` 副标题行（仅保留 💬 图标 + content 文本）。`ConversationItem.preview` 字段因不再使用已删除。
- 改为直连：`fetchConversationList` 不再走 vite 代理，改为直接 `request.get('http://10.89.34.77:8080/session/list')`（base URL 可用 `VITE_APP_DIFY_SESSION_HOST` 覆盖）；同步删除 vite.config.ts 中的 `/dify-session` 代理配置。直连需注意后端 CORS（跨域）是否放行。
- 点击历史项加载真实消息：`DifyRealDialog.vue` 新增 `loadConversationMessages(sessionId)` 调 `GET /session/sessionId?sessionId=<sessionId>（同 host，params 传 sessionId）；接口返回数组，`type 0=用户/1=助手` 映射为 role，`chatTime` 经 `parseChatTime` 转数值时间戳，`sort` 排序。`selectConversation(conv)` 改写：有 sessionId 则拉取真实消息，无则清空。`parseChatTime` 由 "YYYY-MM-DD HH:mm:ss" → "YYYY-MM-DDTHH:mm:ss" 解析。仍为 demo 的部分：初次打开的欢迎语（showWelcomeMessage）、发送消息（scriptEngine.getResponse）仍走 DemoScriptEngine mock，待用户提供对话发送接口。
