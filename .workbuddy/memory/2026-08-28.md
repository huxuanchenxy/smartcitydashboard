## 修复：点击历史后再新建会插入「新对话」且可无限新建
- 根因：`createNewConversation` 里立即 `connectChat(newId)`，服务端马上回 `session_ready` → 触发 `upsertNewConversation` 把空白会话插入列表，并把 `convSource` 改回 `'history'`，导致拦截失效、可反复点击新建。
- 修复：`createNewConversation` **不再预先建 WS**，只做状态重置（`convSource='new'`、`currentConversationId=''`、`currentSessionId=''`、`closeWs()` 断开旧连接、`resetMessages()`）。WS 推迟到真正发消息时由 `sendMessage` 建立。
- `upsertNewConversation` 增加门槛：`pendingTitle` 为空（即未发出过消息）时直接 return，空白新建不会入列表。已有 sessionId 的分支照常置顶高亮。
- `sendMessage` catch 中补 `pendingTitle = ''`，避免发送失败后标题残留污染下一次新建。
- 最终状态机：`none`（初次）→ 点新建提示「已是最新对话」；`history`（选中历史/已发起会话）→ 点新建进入 `new` 空白态；`new` 态发首条消息 → session_ready + pendingTitle 非空 → 入列表并回 `history`。

## 改为两段式 WS 握手（sessionId 完全由后端下发）
- 背景：新会话不能前端生成 UUID 当 sessionId，需后端下发。
- 新流程：发消息时若 `currentSessionId` 为空 → `handshakeNewSession()` 连**无参数** `ws://host/ws/chat` → 服务端在 `session_ready` 中下发 `session_id` → `ensureChatSocket()` 关闭该临时连接 → 用 `ws://host/ws/chat?sessionId=<后端下发>` 重连 → 再 `send({content})`。
- 实现要点：
  - `connectChat(sessionId)`：`sessionId` 为空则 URL 不带参数；`session_ready` 回调中若 `!sessionId` 则调 `handshakeResolve(readyId)` 通知握手完成，否则调 `upsertNewConversation(readyId)`。
  - `handshakeResolve` 提升为模块级 `let`，与 `pendingTitle` 等并列声明（避免在 connectChat 之后声明的可读性问题）。
  - `ensureChatSocket()`：无 sid 先握手；关闭握手连接时先把 `wsSessionId=''` 作废旧连接，避免触发自动重连。
  - **已彻底移除** `crypto.randomUUID()` / `local-${Date.now()}` 等前端生成 sessionId 的代码（全文无匹配）。
- 注意：握手连接仅用于取 id，取到后立即关闭，不承载消息收发。
