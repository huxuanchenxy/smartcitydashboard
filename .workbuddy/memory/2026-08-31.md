## DifyRealDialog 连接失败双重报警合并

- 问题：连接失败时 `socket.onerror` 弹"对话连接出错，请稍后重试"，随后 reject 传到 `sendMessage` catch 又弹"发送失败，连接异常"，一次失败两个 toast。
- 修复：去掉 `onerror` 里的 ElMessage（保留 console.error），用户提示统一由 `sendMessage` 的 catch 弹出（"发送失败，连接异常"）。等待回复中途断线仍由 `onclose` 的 endThinkingState 弹"连接已断开，请重试"，重连放弃时弹"连接已断开，重连失败"，均为单一报警。
- 用户随后指定方向（最终形态）：保留 onerror 的"对话连接出错，请稍后重试"，删除 catch 的"发送失败，连接异常"（catch 只 console.error）。连接失败提示统一走 onerror。

## DifyRealDialog 服务端错误详情透出

- 需求：WS 返回 `{"type":"error","msg":...}`（如后端 SQL 主键冲突堆栈）时，toast 完整展示 msg 内容；聊天框内气泡仍保留"消息处理失败，请稍后重试"。
- 实现：
  - error 分支 toast 改为 `消息处理失败：${data.msg || data.error}`；JSON.parse 失败分支新增 `extractErrorMsg(raw)` 用正则从断裂的原始帧中还原 msg（后端 msg 含未转义换行导致 JSON 断裂的场景）。
  - `endThinkingState` 的 toast：长度 >80 时不自动消失（duration 0 + showClose），customClass `dify-ws-error-toast`；文件末尾新增非 scoped style 块（ElMessage 挂 body，scoped 不生效）设 `white-space: pre-line` 保留换行、max-height 40vh 可滚动。

## DifyRealDialog toast 被对话框遮挡修复

- 问题：DifyRealDialog 是自绘对话框，遮罩 `.custom-dialog-mask` z-index 9999、`.custom-dialog-wrapper` z-index 10000，而 ElMessage 默认 z-index 只有 2000+，toast 被压在对话框后面。
- 修复：全局 style 块里自定义 class 改名为 `dify-real-toast` 并加 `z-index: 10050 !important`（覆盖 ElMessage 内联层级）；本组件全部 8 处 ElMessage（错误详情/连接出错/重连失败/复制成功/复制失败×2/附件上传失败/已是最新对话）统一挂该 class，所有提示都浮在对话框之上。长错误的 pre-line/40vh 滚动样式保留在该 class 下。
- 提示：Element Plus 的 ElMessage options 不支持 zIndex 参数，只能用 CSS !important 覆盖内联样式。
- 用户反馈"报错信息一直停着不消失"后调整：长错误不再 duration 0 常驻，改为 `min(5000 + ceil(len/40)*1000, 15000)` 毫秒自动消失（短错误仍 3 秒），长错误保留 showClose 可提前关闭。
