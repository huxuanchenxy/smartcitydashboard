## DifyRealDialog 连接失败双重报警合并

- 问题：连接失败时 `socket.onerror` 弹"对话连接出错，请稍后重试"，随后 reject 传到 `sendMessage` catch 又弹"发送失败，连接异常"，一次失败两个 toast。
- 修复：去掉 `onerror` 里的 ElMessage（保留 console.error），用户提示统一由 `sendMessage` 的 catch 弹出（"发送失败，连接异常"）。等待回复中途断线仍由 `onclose` 的 endThinkingState 弹"连接已断开，请重试"，重连放弃时弹"连接已断开，重连失败"，均为单一报警。
- 用户随后指定方向（最终形态）：保留 onerror 的"对话连接出错，请稍后重试"，删除 catch 的"发送失败，连接异常"（catch 只 console.error）。连接失败提示统一走 onerror。

## DifyRealDialog toast 被对话框遮挡修复

- 问题：DifyRealDialog 是自绘对话框，遮罩 `.custom-dialog-mask` z-index 9999、`.custom-dialog-wrapper` z-index 10000，而 ElMessage 默认 z-index 只有 2000+，toast 被压在对话框后面。
- 修复：全局 style 块里自定义 class 改名为 `dify-real-toast` 并加 `z-index: 10050 !important`（覆盖 ElMessage 内联层级）；本组件全部 8 处 ElMessage（错误详情/连接出错/重连失败/复制成功/复制失败×2/附件上传失败/已是最新对话）统一挂该 class，所有提示都浮在对话框之上。长错误的 pre-line/40vh 滚动样式保留在该 class 下。
- 提示：Element Plus 的 ElMessage options 不支持 zIndex 参数，只能用 CSS !important 覆盖内联样式。
- 用户反馈"报错信息一直停着不消失"后调整：长错误不再 duration 0 常驻，改为 `min(5000 + ceil(len/40)*1000, 15000)` 毫秒自动消失（短错误仍 3 秒），长错误保留 showClose 可提前关闭。

## DifyRealDialog 历史会话删除功能

- 需求：鼠标悬停历史会话项 → 末尾出现删除按钮（🗑）→ 点击后 ElMessageBox 二次确认 → 删除。
- 接口（用户确认）：`DELETE /api/session/{sessionId}`（base 同 VITE_APP_DIFY_SESSION_HOST）。
- 改动：
  - 模板：conversation-item 内新增 `.conversation-delete-btn`，`@click.stop` 防触发 selectConversation。
  - 脚本：`confirmDeleteConversation(conv)`（ElMessageBox.confirm 确认后调 request.delete；sessionId 为空的本地 pending 项只本地移除）；`removeConversationLocally(convId)`（删除的是当前选中会话时回退到 new 空白态 + closeWs + resetMessages）。成功/失败均有 toast。
  - 样式：删除按钮 opacity 0 默认隐藏、`.conversation-item:hover` 显示、hover 变红；全局 style 块新增 `.dify-real-toast.el-message-box` 抬升确认框 z-index（MessageBox 同样挂 body、会被自绘对话框遮挡）。
- 注：响应拦截器对非 200 code 会 reject，删除接口需返回 code 200 才视为成功。
- BUG 修复「点击历史对话全部选中」：curl 实测 GET /api/session/list 返回的记录**没有 id 字段**，主键是 autoId（另有 sessionId/tSessionId/name/createdOn 等），前端 `String(item.id)` 使所有项 id 均为 "undefined" → :key 冲突 + `conv.id === currentConversationId` 全成立。修复：列表项 id 改为 `autoId`（兜底 sessionId，再兜底 `hist-${index}`），rawList 类型同步更新为 autoId?: number。删除/详情/占位逻辑均用 sessionId，不受影响。
- 删除确认弹窗改为自定义 div：Element Plus 的 ElMessageBox 在自绘对话框内出现左上角几乎不可见（系统共性问题）。新增 `confirmDialogVisible/title/message/pendingDeleteConv` 状态，`openConfirmDialog/closeConfirmDialog/onConfirmDelete` 函数；模板内 custom-dialog 中渲染 fixed 居中遮罩弹窗（z-index 10100），带「取消/删除」按钮、点击遮罩关闭；样式含淡入缩放动画、白底卡片、删除按钮红色高亮。移除 `ElMessageBox` import 与相关样式。
- BUG 修复「点删除弹窗不出现」：options API（defineComponent+setup return）写法下，`confirmDialogVisible/Title/Message` 三个状态忘了加进 setup() 的 return 对象 → 模板 v-if 恒 undefined。教训：此组件新增模板引用的任何变量都必须同步加到 setup return（约 2140 行处的 return {...}），与 script setup 不同，漏了不会编译报错、只静默失效。
- BUG 修复「弹窗出现但删除/取消按钮点不动」：AST 解析确认确认弹窗是 `.custom-dialog-mask`（外层遮罩）的直接子节点；对话框以 no-mask 模式（可拖拽悬浮窗）打开时外层遮罩 `pointer-events: none`，confirm-mask 未显式设置时继承 none → 所有点击穿透。修复：`.dify-real-confirm-mask` 加 `pointer-events: auto`。教训：Teleport 自绘弹窗里挂在遮罩 div 下的元素，必须显式恢复 pointer-events。

- BUG 修复「MdEditorDialog 窄窗口时浏览器全屏/预览按钮被截断不可见」：根因是 md-editor-v3 库自带 `.md-toolbar{min-width:850px}`（写死）且 `.md-toolbar-wrapper` 为 `overflow-x:auto` + 隐藏滚动条（scrollbar-width:none / ::-webkit-scrollbar height:0），窗口变窄时右侧组（pageFullscreen/preview，靠 space-between 顶到最右）超出可视区且无法滚动。修复：组件内 :deep() 覆盖——wrapper 改 height:auto + overflow:visible，.md-toolbar 改 min-width:0 + flex-wrap:wrap，.md-toolbar-left 也加 flex-wrap（停靠模式最小 360px 时左侧也可能溢出）。宽窗口布局与原来完全一致。
