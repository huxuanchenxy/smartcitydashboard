# 2026-09-18

## 发布页匿名访问接入 DifyRealDialog（接手 qoder 未完成部分）

场景：`#/publish/346?token=xxx` 匿名访问大屏内的 VAiDifyReal → DifyRealDialog，
不得使用 localStorage 的 loginAccount，上传 / 聊天接口都要把 URL token 作为 loginAccount 参数。

已完成：
- 新建 `src/utils/dify-request.ts`：Dify 后端专用纯净 axios 实例（无 baseURL / 无拦截器）。
  关键原因：全局 `@/utils/request` 的 needLogin 拦截器会 `config.headers.post.token = getToken()`
  **覆盖**掉显式传入的 token 头，且响应拦截器 401/403 会 removeToken + 跳 /login（匿名用户被误踢）。
- DifyRealDialog 四个 HTTP 接口（session/list、chat/sessionId、session/delete/{id}、file/upload/batch）
  全部切到 difyRequest，并统一带 `X-Src-System` + `token` 头（新增 `getAuthHeaders()`）。
- `getLoginAccount()`：anonymous=true 时**只**用 props.loginAccount（URL token），不回退 localStorage。
- WS 消息体新增 loginAccount（+ 已有 sessionId），与握手 URL 上的 loginAccount 保持一致。
- wrapper（ai-dify-real / ai-dify-demo）anonymousToken 改为 computed，响应 hash 路由变化。
- `token-util.ts` 中重复的发布页判定删除，改为 re-export `@/utils/dify-publish`（只有一份实现）。
- 匿名且 role 为空时显示名兜底「匿名用户」，避免侧栏底部空白。

验证：vite dev 转译 DifyRealDialog / 两个 wrapper / dify-request / token-util 均 200，无编译错误。
